Git, GitHub, CLI

Git - система контролю версій
 VCS - Version Control System
 SCM - Source Code Management
https://git-scm.com/
Це програма, що встановлюється на локальний ПК
(не у мережі) і забезпечує управління версіями.

Версія - певний стан проєкту, якому надається номер
або назва. А також публікується. І продовжується
робота над наступними версіями. 

Ідея управління версіями - збереження лише змін,
що вносяться по відношення до попередньої версії.

Коміт (Commit) - фіксація версії - збереження 
поточного стану проєкта. Щось схоже на архів 
внесених змін. 

Існує декілька систем іменування (нумерування)
версій:
 - Major.Minor.Patch (1.0.1) - остання цифра (Patch)
   змінюється, якщо версії повністю сумісні,
   незначні виправлення чи декоративні доповнення.
   Minor - більш масштабні зміни зі збереженням 
   загальної сумісності.
   Major - перехід до нової стадії проєкту, 
   несумісність з попередньої версією. 
 - Рік-півріччя: 2026.2   

-------------------------
CLI - Command Line Interface - інтерфейс 
взаємодії з програмою шляхом її запуска з 
передачею додаткових параметрів. Зазвичай,
засобами Терміналу (PowerShell, Bash)
Наприклад, 

git config --global user.name "Your Name"
git config --global user.email "youremail@example.com"

  git - назва програми (git.exe)
  все інше - параметри, що є суттю CLI
деталі - https://git-scm.com/cheat-sheet

--------------------------
GitHub - сайт, який надає місце для розміщення
власних репозиторіїв, їх комітів у мережі. 
Альтернативи: dev.azure.com, bitbucket.org, gitlab.com
--------------------------

Порядок роботи
- створити (ініціалізувати) репозиторій
git init
- вказати які файли будуть у репозиторії 
git add .
("." означає поточну директорію, тобто додати все з папки)
- створити перший коміт
git commit -m "Назва коміту"

= створити обліковий запис GitHub (або іншого сайту)
= опублікувати репозиторій на GitHub

--- всі ці дії можна перекласти на Студію ---
відкриваємо лівий блок "Source control" і
вибираємо "Publish to GitHub"
перше натиснення може запросити авторизацію,
тоді треба буде натиснути другий раз
--------------
Потенційні проблеми:
- забули ввести user.name, user.email
  при цьому виникає проблема, що репозиторій створюється, 
  але зв'язок з ним не встановлюється. Після налаштування
  user.name, user.email операція завершується помилкою
  "такий репозиторій вже існує"
  В такому разі заходимо до GitHub у браузері та 
  = копіюємо адресу (remote), вставляємо в Студії
     на її запит
  = якщо попередній пункт не вдалось виконати, то видаляємо
     цей порожній репозиторій через вкладку Settings
     і повторюємо процедуру публікації

Д.З. Використати CLI для збереження змін у репозиторії
- змінити HTML-файл, додати декілька кнопок, що запускають різні повідомлення
- подати команди через CLI: add, commit та push з необхідними атрибутами
- зробити скріншот Терміналу з командами та їх результатами,
   прикласти до звіту з ДЗ, посилання на репозиторій - у коментарі
